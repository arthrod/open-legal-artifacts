Fact chronology

A timeline where every fact carries its evidence — and every judgment is machine-checked: near-duplicate facts across documents are merged into one multi-source entry, each quote is verified against the source text (verbatim / approximate / unfound), facts are tied to the case theory (🔴/🟡/⚪ with [SME VERIFY] on borderline calls), privilege-flagged documents are tracked, and three variants (working / statement of facts / witness prep) render from one deterministic core with reproducible version diffs. Open reimplementation of Anthropic's closed artifact.

Worked example (fictional): Delgado v. Summit Ridge Hospitality — 10 facts across 5 documents; one hire reported twice (merged), one termination date the complaint and letter disagree about, one deposition quote that is only an approximate match, one quote the machine cannot find at all.

Your own chronology

Bring your own facts: edit the JSON (schema in spec.md) or import a .docx — the free live AI extracts dated events with verbatim quotes (previewed and editable before anything lands), and the imported text is added as a document so every quote is machine-checked (verbatim / approximate / unfound). Ambiguous dates stay in dateLabel with date:null; nothing is invented. Nothing above changes until you click Build chronology — the worked example is the default.

Deterministic core — an optional LLM may extract { date, topic, text, source quote } tuples from documents (schema in spec.md); the core never guesses a date or a topic. Significance tags are deterministic key-term ties for attorney review; divergent-account flags are potential conflicts, not legal conclusions. Statement-of-facts and witness views exclude privilege-flagged documents only as a drafting aid — privilege calls belong to counsel. All example data fictional.
