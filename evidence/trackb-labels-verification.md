## 4. Deviations from the plan

1. **Page-size fallback triggered (M2 signal).** Importing the vendored
   module data-URI-inflated cite-check/tabular-review/playbook past the
   80 KB val cap (93.4/93.5/95.3 KB chars). Per the plan's own fallback,
   those three demos now PASTE a compact per-demo label block (table +
   canonical map + legend); the canonical engine + exhaustive-inventory
   test stay in `_shared` and each demo's `core/display-labels.js` is
   still vendored and byte-parity-tested (imported by nothing on those
   three pages). Final sizes: cite-check 78.5 KB chars / 80,626 B,
   playbook 79.6 / 81,682, tabular 79.2 / 81,279 (HEAD: 76,844 / 79,279 /
   77,543 B). All three exceed the 78 KB char warn line — unavoidable:
   HEAD headroom to it was ≤1.2 KB (playbook was already over). They stay
   under 80 KiB; if Val Town's cap is 80,000 BYTES, all three are over by
   ≤2.1% — flagged for the parent to confirm the unit or trim further.
2. **7 per-demo screenshots**, not the plan's 10 named shots (task brief
   specified one `<name>.png` per demo).
3. `collapseBoilerplate` grew an explicit `{keepFirst:false}` option (the
   cross-card “render once at section head with count” case); default
   semantics match the acceptance text (keeps first, drops repeats, counts).
4. `renewal-calendar` "later" tier label is “Due later”, not the plan's
   literal “later” (the inventory test requires label ≠ raw key).
5. Matter-board does not adopt the five-label lexicon (per plan §4:
   deadline states are not verdicts) — labels + ink only, no legend line.
